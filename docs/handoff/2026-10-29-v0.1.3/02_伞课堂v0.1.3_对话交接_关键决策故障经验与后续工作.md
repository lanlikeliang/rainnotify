# 伞课堂 v0.1.3：对话决策、故障经验与后续工作交接

交接日期：2026-10-29。配合 [项目说明与验收](01_伞课堂v0.1.3_项目说明_架构功能与阶段验收.md) 阅读。本文件提炼可复用经验，不复述全部聊天，也不把历史授权扩展为未来所有操作的授权。

## 1. 已确认的要求与协作偏好

- 用户要能直接安装使用的独立手机 App；正式版叫“伞课堂”，GitHub 仓库继续叫 RainNotify，已同意公开并提供 APK。关于与帮助应保留仓库链接。
- 首阶段普通版雨课堂、Android 16，主要实测 Xiaomi 14。多品牌是目标而非已完成验收；不自行降低最低系统或扩展学校版本。
- 手机直接调用 API，不部署服务器。曾考虑 GLM、Kimi、DeepSeek、豆包手机 App，但正式路线已明确 **只保留 API**；当前实现仅 DeepSeek，不把可扩展性说成已接入其他服务。
- 用户接受本 App 必要的通知、自启动、省电无限制和后台联网配置。无需 AI App 常驻、关联启动或无障碍；不保存、代输锁屏密码。
- 入课要求已经改为 **明确提示用户自行微信扫码**。保留 App 选择课堂是为了指定监听目标，连接成功不冒充签到成功。
- 课堂／题目／设置三页；大胶囊三选一：关闭、发题通知、自动答题，当前档位一眼可见。首次引导与后续使用保持同一布局，缺配置时就近解释并提供入口。
- 课堂显示当前账户、课堂和模型；最新题仅保留关键时间、类型、答案、状态。不要恢复无信息量的标语、重复“监听已关闭”或“最近处理”。
- 用户先要求删除历史演练，后来明确要求按课堂保存所有题和复习导出；两者不冲突。保留复习，不恢复测试按钮、题目导入或模拟发题的产品入口。
- 五题型：单选、多选、填空、投票、文字主观；主观答案言简意赅。原始 90 秒需求是完成时效目标，不是忽略服务器截止时间的依据。
- 用户希望减少无谓确认。能通过代码、文件和脱敏日志查清的先查；确需手机动作、实际听声、课堂观察或账号授权时，给出一次清晰操作和结果反馈问题。账号登录与 Key 输入由用户在设备上完成。
- 发布、安装、真实入课和真实提交属于不同动作。维护文档或离线回归不自动包含新的课堂提交任务；不能为验证而操作正在进行的课堂。

## 2. 路线演变：哪些经验保留，哪些功能不恢复

| 阶段 | 收获与现行结论 |
| --- | --- |
| 0.0.3–0.0.9 通知与监听 | 实测证实通知权限、通知渠道、音量、厂商省电是不同因素；普通版授权／课堂监听和其他 App 前台时的新题提醒跑通。 |
| 0.0.10–0.0.11 题目采集 | 获取题干、选项、原图，志愿者手动导出实测题。真实资料保留在本地，不进入公开仓库。 |
| 0.0.12–0.0.16 AI App 实验 | 分享图文、创建对话、发送、回读、冷启动、版本变化都需要适配；安全锁屏要求解锁。留下调研经验，正式版不再维护该链路。 |
| 0.0.17–0.0.19 协议与 API | 修复题图临时授权变化导致的身份误判；接入 DeepSeek API 和五题型。用户已完成真实 API 自检及短时熄屏演练；不等同所有真实课堂题型提交通过。 |
| 工具链迁移 | 正式工程改为英文路径、Wrapper、Git、CI、正式签名；不再依赖原型临时盘符映射。 |
| 0.1.1／0.1.2 internal | Compose 三页、三档模式、API-only、模型选择与黑白图标。 |
| 0.1.3-internal / 24 | 课程名、扫码提示、模式保护、原图采样、来源返回、课堂归档、HTML 导出、连续题队列与重连补收。 |
| 0.1.3 / 25 | 更名“伞课堂”、关于页 GitHub 链接、公开发布与安装文档；沿用 24 版课堂处理逻辑。发布已完成，不需要接手者再发布同一版。 |

## 3. 典型故障与复用经验

| 现象 | 已知原因／处理 | 接手时不要犯的错误 |
| --- | --- | --- |
| 通知栏有消息，没有横幅、声音或熄屏延迟 | 横幅曾受系统临时屏蔽影响；省电从限制改无限制后熄屏约 30 秒有声；后续 API 结果无声曾是通知音量未开。 | `notify()` 成功只证明提交了通知，不证明用户看见／听见。分别记录事件、通知和用户观察，不盲目叠加唤醒锁。 |
| 微信确认网页登录，回 App 仍未登录／网络失败 | 早期授权会话及后台网络需要修复；用户后来确认 0.0.6 登录成功。 | 旧二维码可能失效；不要索取 Cookie、二维码或 Key。区分网络失败与授权过期，不把所有异常都清登录。 |
| 能识别课堂却不能直接入课 | 授权账号与微信扫码入课不是同一步，接口曾返回 HTTP 400／扫码要求；当前明确要求人工扫码。 | 课后读取 HTTP 401 不足以证明课堂中协议损坏。保留连接目标与服务端确认，不循环调用可能影响签到的接口。 |
| “题目或选项发生变化”，求解前或提交前均可能出现 | [QuestionIdentity](../../../android-app/app/src/main/java/cn/rainnotify/app/answer/QuestionIdentity.kt) 只在已知普通版图片 HTTPS 主机上忽略临时 `auth_key`，仍比较题型、内容、选项映射、资源路径等。 | 不移除全部查询参数、不放宽任意主机、不取消二次校验。诊断仅记录差异类别，下载仍使用完整签名 URL。 |
| API 能看图，UI 原图不可用 | [ImageSampling](../../../android-app/app/src/main/java/cn/rainnotify/app/ui/ImageSampling.kt) 修正采样起值及有界计算；原图文件并未因此重写。24 版显示／全屏已验证。 | 先区分下载、存储、解码和显示。双指缩放未单独验收，不能从全屏显示推断通过。 |
| 点自检后自动档变通知档 | 24 版统一拦截运行中配置修改，保持原模式，提示用户先切档；正常故障降级仍保留。 | 模型切换、Key 保存／删除也要覆盖；不能修一个按钮留下其他隐式降级入口。 |
| 从课堂子页返回到设置 | 保存来源导航；设备测试覆盖账户、课堂、模型返回及设置来源。 | 不把所有子页返回目标固定成设置；检查通知入口与题目列表来源。 |
| 忙于一道题时漏掉下一道 | `PendingAnswers` 排队、去重、原时限保护；采集异步；重连补收未见时间线。 | 排队不能延长截止时间；首次时间线不自动答；进程被杀、服务器不补发、同 ID 重发仍有限制。 |
| Windows CI 的 HTTP 测试偶发超时 | MockWebServer 显式绑定 IPv4 回环；普通 API 用例预算 10 秒、取消测试有界等待；提交测试必须遵守生产允许的 1–8 秒范围，最终用 8 秒。 | 早期尝试给提交测试 10 秒违反契约，已修正。不要为了绿色 CI 放宽生产超时、关掉校验或无上限等待。 |
| Android Studio 启动失败／源码校验／代理弹窗 | 曾遇 `.port`、DirectoryLock 和源码依赖摘要问题，后续启动及构建已完成；本机详情见独立交接。 | 不把历史“待同步”当当前故障；无新证据不重装、不删除整套 IDE 配置、不关闭依赖校验。 |

## 4. 脚本、文档与发布纪律

当前标准操作以 [DEVELOPMENT](../../DEVELOPMENT.md) 为准。以下旧工具仍在仓库，**文件存在不代表可用**：

| 工具 | 状态 |
| --- | --- |
| `tools/run_ai_rehearsal.ps1` | 调用已删除的 `RehearsalProbeActivity`，不是正式版入口。 |
| `tools/run_api_type_probe.ps1` | 调用已删除的 `ApiTypeProbeActivity`；不要用来宣称现在有设备端演练。 |
| `tools/check_accessibility.ps1` | 针对已删除的 Kimi 无障碍服务，当前产品不适用。 |
| `tools/read_answer_state.ps1` | Debug 专用 `run-as` 读取工具，含旧无障碍注释；不是 Release 诊断，默认不要启用输出答案的可选参数。 |
| `tools/compare_question_snapshot.ps1` | 当前 Debug 只读比较入口仍存在；仅在用户授权、需要定位差异时使用，课后接口可能不可读。 |

本次只标明历史状态，未改动／删除工具或内部 ZIP、REHEARSED 等兼容类型。内部命名或合成测试不意味着可以恢复用户可见入口。后续若清理旧工具，单独做可审核变更。

真实题目、导出、PDF、截图、日志、Key、会话和签名私钥不进 Git。脱敏诊断不含题干、答案或认证字段。发布前既审当前源码，也审可达历史；上次公开前已检查 25 个提交／308 个 blob，无检测命中，但这不是以后免检的凭证。

继续使用 `cn.rainnotify.app` 与原正式证书；不运行初始化脚本替换已有密钥。25 版 Release 已公开，后续发新版需要更高 versionCode、新版本标签与重新验证。文档交接不会自动产生新 APK，也不覆盖旧标签／附件。

## 5. 下一阶段如何开始

本次没有未完成的发布任务，也没有承诺自动启动下一阶段。新对话先读交接、检查 Git 差异，再按用户的新目标行动。

| 优先项 | 状态 | 建议验证方式 |
| --- | --- | --- |
| 真实课堂连续题、重连、扫码后的课程反馈 | 尚未全面验收，不是已知必现失败 | 用户提供课堂时间与授权后，记录阶段状态，核对微信结果；不假装拥有可控教师发题环境。 |
| 五题型全部真实提交回执 | 合成流程通过，真实覆盖不足 | 使用自然出现的各题型，逐类记版本、时限、模型与回执，不将单次成功扩大成全部通过。 |
| 长时熄屏、多品牌 | 待验收 | 分开记录后台配置、网络、系统清理与服务状态；此前短时演练不能替代长时。 |
| 图片缩放、桌面图标 | 显示／全屏已验，手势与跨桌面裁切未全验 | 指定版本和设备观察，保留必要的本地证据。 |
| 签名恢复备份 | 是否完成未知 | 先向用户确认已有备份；需要时让用户在自己的终端设置备份密码，勿在聊天索取。 |
| 文档与旧工具债务 | 本次整理导航，旧脚本未清理 | 后续单独评估移除，避免与协议修改混在一起。 |

手机当前是否连接、是否授权、是否在课中、是否已安装 25 版均要重新查证。历史“10 月 9 日 13:30–15:05”仅是已过去的测试安排，不是未来日程。旧对话里的手机操作确认不等于现在的设备状态。
