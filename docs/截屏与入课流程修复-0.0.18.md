# 截屏与课堂入课流程修复（0.0.18）

交付日期：2026-10-23。设备：Xiaomi 14 / Android 16。

## 截屏问题

原来登录、题目、AI 设置、AI 图文自检、作答和自动唤起页面均主动设置 `FLAG_SECURE`，使系统拒绝截图或捕获内容为空。这是辅助 App 自身的限制。

本版解除上述六处限制，保留作答期间需要的保持亮屏标志。主页面原本没有禁止截屏。源码中已无 `FLAG_SECURE`。

0.0.18 覆盖安装后，在确认本 App 登录页位于手机前台的条件下，使用系统屏幕捕获读取画面，生成 1200 × 2670 PNG，已视觉核对登录状态、课堂列表和按钮均完整可见。截图仅留在 `.local-tools/` 私有验证目录，不随 APK 或安装包分发。其他页面采用同一解除方式，但本次没有逐页实机截图。

## 入课失败的确定原因

手机保留的诊断有 5 次 `lesson_checkin` 返回 HTTP 200、业务码 50070，随后有成功获取课堂凭据并完成连接的记录。HTTP 成功不等于业务允许入课。

此前读取的[雨课堂官方课堂脚本](https://fe-static-yuketang.yuketang.cn/fe/static/lesson/3.3.236/js/fullscreen.9a6559b7a061cfe67e80.js)将 50070 映射为动态二维码签到要求。官方课堂业务模块也专门处理该码：[业务模块](https://fe-static-yuketang.yuketang.cn/fe/static/lesson/3.3.236/js/12.2c1823b4b49f34618d9e.js)。因此这几次失败已经能确定是服务器要求课堂动态码，并非因为没有识别到账号或课堂。

账号授权二维码用于登录；教师展示的课堂二维码用于本节课的签到。看见课堂列表不代表通过这节课的签到检查。动态码课堂仍需有效的现场二维码，辅助 App 不能仅凭课堂编号替代该验证。本版解决错误提示和操作衔接，没有实现免扫码进入动态码课堂。

## 新流程

1. 登录后点击“入课并监听”，确认可能记录签到后发出一次正常入课请求。普通课堂不再被页面文案要求先到微信入课。
2. 若雨课堂返回 50070，保留所选课堂，显示明确说明，不再建议重新授权账号。
3. 点击“去微信扫码，返回后继续监听”，手动扫描教师当前展示的二维码并完成签到，然后返回本 App。
4. 本页在用户返回后尝试为同一课堂接续一次入课，后续以服务器回执和 WebSocket 握手确认是否监听成功。
5. 也可自行完成扫码后，点击“已完成课堂扫码，继续监听”。

返回接续只在用户明确点击相关按钮后启动，必须发生离开/返回，限时 5 分钟。切换课堂、登录状态不可用、页面重建、取消或超时都会使自动接续失效。进程重启不会自动入课；需要手动重新选择课堂。未完成扫码就返回，服务器仍可拒绝，不会循环重试。仅重新打开登录页不会发起入课。

请求仍使用原先核对过的 `source=5`，没有改写来源来伪装扫码，也没有猜测或生成动态码参数。入课 POST 与监听重连不增加自动网络重试。
