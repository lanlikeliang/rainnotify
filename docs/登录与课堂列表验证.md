# 普通版登录与课堂列表验证

更新：2026-10-04；本页记录 0.0.5–0.0.7 的登录验证。后续监听实现见 [单课堂监听验证](单课堂监听验证.md)。是否在真实账号上通过，以末尾实测状态为准。

## 本次范围

在现有 Android 16 通知验证 App 中新增独立登录页，执行普通版扫码授权、登录校验、姓名显示和正在上课的课堂列表查询。此版本没有入课、签到、答题或课堂消息监听代码。没有课程进行中时，列表为空是有效结果；格式错误或服务端拒绝不会被显示成“没有课堂”。

扫码产生的授权材料只用于向普通版雨课堂换取会话。会话经 Android Keystore 中的 AES-GCM 密钥加密后写入本机 no-backup 私有目录；退出辅助 App 登录时删除密文和密钥。二维码、账号姓名、Cookie、授权材料与接口响应正文均不写入诊断。

## 已核对的候选接口

| 步骤 | 路径与方法 | 作用 |
| --- | --- | --- |
| 请求二维码 | WSS www.yuketang.cn/wsapp/，requestlogin | 请求网页角色的登录二维码图片地址 |
| 微信确认后换取会话 | POST /pc/web_login | 将授权响应中的 UserID 与 Auth 作为 JSON 提交，接收 Cookie |
| 校验会话 | GET /api/v3/user/basic-info | 检查业务结果 code 是否为 0 |
| 显示授权账号 | GET /v2/api/web/userinfo | 读取姓名供用户在手机上核对，失败时仍可显示登录已校验 |
| 查询当前课堂 | GET /api/v3/classroom/on-lesson-upcoming-exam | 仅解析 onLessonClassrooms，读取课堂名称和 lessonId |

这些是社区源码观察到的候选内部接口，不是平台公开稳定 API 承诺。独立用 Kotlin 实现最小范围，未运行参考项目或引入其自动课堂操作。

## 手机上的操作

1. 打开“普通版雨课堂登录与课堂列表”，点击生成二维码。
2. 点击“保存本次二维码到相册”，打开微信扫一扫，从相册选择最新二维码并确认授权；随后返回辅助 App。
3. 查看手机显示的账号是否正确，以及当前课堂列表。无需把姓名或登录材料发到聊天。
4. 退出此页再重新打开，检查已保存会话能否重新校验。
5. 需要清除时，使用“退出辅助 App 登录”；该操作只清除本 App 本地会话。

登录页使用 ViewModel 保留切换 App 与旋转时的流程。登录等待有本地超时；取消、超时和重新开始都会使旧回调失效。通过按钮写入相册的二维码由本 App 跟踪，流程完成／失败／取消／下次打开登录页时尝试清理；若系统拒绝清理，记录无敏感信息的错误，用户可自行删除副本。

## 验证要点

- 登录：微信能否从相册识别二维码、是否需要额外确认、返回辅助 App 后会话是否有效。
- 空列表：非上课时间返回空列表是正常情况，不等同于真实课堂监听通过。
- 会话保存：重新打开登录页后不必再次授权；实际有效期按服务端校验结果，不硬编码天数。
- 会话隔离：Cookie 只发给普通版固定源站，不随二维码下载发送，禁止自动重定向到其他站点。
- 异常：取消后的迟到授权不能恢复登录；接口异常要显示失败；诊断只记录请求阶段、HTTP 状态、数字业务码与课堂数量。
- 仍待课堂验证：微信与辅助 App 同课堂共存、手动入课的副作用、新题事件、后台网络与长期熄屏。

## 当前实测状态

0.0.5 已构建并通过 ADB 安装、启动，正在等待用户完成微信授权。8 项 JVM 单元测试通过（0 failures、0 errors），覆盖 Cookie 域名／路径／过期、协议异常与空列表区分、迟到回调作废、凭据不进入诊断、请求路径及拒绝自动重定向。测试使用合成数据，没有调用真实账号。

Android lint 为 0 errors、14 warnings、2 hints；警告涉及依赖版本更新建议、KTX 写法和后台线程中有意同步提交的二维码副本追踪记录。构建脚本已解决 Windows 中文路径导致 Gradle 测试运行器无法启动的问题：临时将同一工作区映射为可用 ASCII 盘符，运行结束后取消映射，没有移动工程或复制账号数据。

0.0.5 真机结果：WSS 握手成功，二维码图片请求返回 HTTP 200；用户确认微信可识别二维码，并提示已登录雨课堂网页版，但返回辅助 App 后仍未登录。几次脱敏记录显示授权等待期间连接失败，没有 login_verified 或课堂查询记录。说明二维码与微信确认步骤可用，但授权结果接收／会话交换尚未通过。

0.0.6 补充二进制 JSON 消息处理（参考 Python 接收逻辑原本支持字符串与字节两种消息），增加仅含异常类名的网络诊断和登录页前后台事件。9 项单元测试全部通过，其中新增 MockWebServer 二进制授权消息测试；构建与 lint 完成并已安装。

0.0.6 首轮用户仍反馈网络连接失败。报告 probe-20261003-160419-utc.jsonl 显示：二维码下载成功；切到后台后出现 SocketException，返回登录页前后记录失败，未执行会话交换。此时 battery_optimization_exempt=false，与 0.0.4 熄屏成功时的 true 不同。正在同一版本上请用户核对省电条件；尚不能断言设置变化由 APK 更新引起，也不能断言二进制消息就是原始根因。

同一版 0.0.6 后续复测通过：用户反馈“登录成功，账号正确”。报告 probe-20261003-160729-utc.jsonl 中省电豁免为 true，记录 login_verified、session_saved=true，并成功返回课堂列表（lesson_count=0）。用户随后刷新时，多次从加密文件读取会话、通过服务端校验，并再次取得空课堂列表。真实登录、短间隔会话恢复与非上课时的课堂查询已通过；没有验证课堂入课、真实发题或整个课时后台连接。

0.0.7 已安装并验证升级后会话恢复。报告 probe-20261004-000804-utc.jsonl 中版本为 0.0.7-auth-probe，出现 session_restored 事件且 authenticated=true、session_saved=true，课堂查询 HTTP 200、lesson_count=0，省电豁免仍为 true。无需重新扫码。新增登录前提示：Xiaomi 且标准省电豁免未开启时，说明本机已观察到的中断现象，提供本 App 设置与标准电池优化列表，并允许继续授权。此检查不是所有 Android 登录都必须具备的权限门槛。
