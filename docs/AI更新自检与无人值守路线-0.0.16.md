# 0.0.16：AI 更新后自检与无人值守路线

## 用户可操作的验证路径

进入「AI 设置」→选择 Kimi、DeepSeek 或豆包→「所选 AI 更新后图文自检」：

1. 登录所选 AI，保持手机解锁。
2. 运行「验证单选 · 1 张原图」，等待结果通知后返回自检页。
3. 运行「验证多选 · 2 张原图」，等待结果通知后返回自检页。
4. 两项均通过后，该安装版本可参与正式作答和本次课堂自动模式。

每次生成随机选项位置的本地测试图，正确选项仅存在于图片中，未写进提示词。测试检查原图附件、自动发送、最终回复、本题唯一标识、JSON 格式、答案与已知图像内容一致。它不访问真实课堂提交接口，不要求已有课堂题目，也不会把测试题放进用户的题目导出库。测试图片和提示词会发送给用户选定的 AI 服务。

验证记录绑定 AI 包名、版本名、版本代码、安装更新时间、本 App 的适配规则修订号和系统构建。更新或重装 AI、更换相关系统构建、适配规则变化后，旧记录不能放行新环境。辅助 App 普通覆盖升级不会无条件清空记录。重新运行某项自检时先撤销该项旧记录，中断或失败后需重试。

未验证的新版本仍可手动演练历史题，但不能正式提交或进入自动模式。历史题演练成功不会自动代替已知答案自检。用户可看到两项分别通过与否、通过时间、最近失败原因。所有 AI 使用同一条自检路径，不再比较「已安装版本必须等于写死版本」。

自检仅证明当时基础图文交互可用，不等于模型知识准确率、所有题图数量与布局、长时后台稳定性或真实雨课堂提交已通过验收。服务端灰度、模型切换、网络错误也可能在版本号不变时影响表现；可重新自检，运行中仍保留附件、页面、发送次数、答案格式与时间校验。

## 调用 AI App 的实际依赖

| 环节 | 当前依赖 | 更新可能带来的影响 |
| --- | --- | --- |
| 打开 App | Android 包名及系统启动入口 | 包名、登录或首次启动流程变化可能阻断 |
| 传入图片和文字 | Android ACTION_SEND / ACTION_SEND_MULTIPLE、FileProvider 临时读取授权；接收方公开的分享 Activity | 接收入口、支持 MIME 类型或分享后的行为可能变化 |
| 新对话、附件核对与发送 | 无障碍节点的语义描述、部分控件 ID、层级和相对位置 | 页面重做、描述改名、加载方式变化可能需要修改适配 |
| 读回答案 | 可读取的最终文本、回复操作标志、本题随机标识、严格 JSON | 新渲染组件、完成标志变化或模型未遵从格式可能导致停止 |
| 从熄屏开始 | 本 App 后台运行与启动界面条件、系统锁屏状态 | 厂商限制或安全锁屏可能要求人工处理 |

新版分享模块查询所选包公开声明、启用、导出的匹配分享入口。优先采用已适配入口；旧入口改名且只剩一个明确匹配入口时可尝试该入口。候选缺失或多个未知入口时停止，不猜测，也不自动重复发送。当前 Kimi 3.1.4 同时声明了通用外链和图片入口，因此仍优先选择已确认的图片入口。

Android 的分享协议和无障碍 API 是公开系统接口，但 AI App 的页面布局及接收行为并不是稳定的求解接口。小版本更新不必然失效，版本号相同也不能保证页面永不变化。自检可以减少每次小更新都发布辅助 App 的需要，无法自动修复所有未知界面。

依据：[Android 分享文档](https://developer.android.com/develop/ui/compose/sharing/send)、[AccessibilityNodeInfo](https://developer.android.com/reference/android/view/accessibility/AccessibilityNodeInfo)。

## 安全锁屏与完全无人值守

当前实现使用系统 `requestDismissKeyguard`。Android 官方说明：没有安全锁屏或系统判定为可信状态时可直接解除；有安全锁屏且不在可信状态时，会显示凭据验证界面。普通 App 没有通过该公开接口传入 PIN 并直接解锁的能力。

把已知密码保存后模拟点按锁屏键盘，在某些设备和授权环境下可能可行，但依赖锁屏控件、厂商策略和当前认证页面；失败尝试可能触发系统等待，还会让辅助 App 持有整部手机的解锁凭据。因此不作为跨 Android 16 品牌的可持续实现，本版本没有密码录入、保存或代输功能，也未修改手机锁屏设置。

可选路线：

| 路线 | 人离开设备后能否继续 | 条件与取舍 |
| --- | --- | --- |
| 现有 AI App + 安全锁屏 | 锁定后不能保证继续，需要系统验证身份 | 继续保留当前唤醒与解锁后自动接续 |
| 专用测试设备无安全锁，或开始后一直保持解锁亮屏 | 可以尝试 | 用户自行决定设备安全配置；增加耗电，仍受页面和后台唤起影响，需要单独验收 |
| 手机直接调用视觉模型 API | 不需要打开 AI 界面或解除普通屏幕锁 | 推荐作为保留安全锁屏的无人值守方向；仍需网络、模型费用、后台运行与长时熄屏验收 |

API 路线无需自建服务器：手机监听雨课堂 → 下载题干、选项、原图 → 在本 App 服务内调用视觉模型 → 校验结构化答案 → 检查课堂时限及状态 → 提交一次 → 记录回执。模型服务仅接收题目，不应收到雨课堂登录凭据。API 密钥应由用户在本 App 输入并使用 Android Keystore 保护，不能写入 APK 或诊断日志。云端 API 的版本、模型和限额仍需维护，但不会随着手机 AI App 的 UI 更新而失效。

视觉能力可参考 [智谱对话补全文档](https://docs.bigmodel.cn/api-reference/模型-api/对话补全)；本版尚未接入 GLM API。即便使用前台服务，长时熄屏也不能一概保证实时联网；Android Doze 会限制网络和唤醒锁，需要本 App 后台设置、适用的电池优化豁免及实测。API 消除了界面和解锁依赖，不能替代监听稳定性验证。

依据：[Android KeyguardManager](https://developer.android.com/reference/android/app/KeyguardManager#requestDismissKeyguard(android.app.Activity,%20android.app.KeyguardManager.KeyguardDismissCallback))、[Doze 与 App Standby](https://developer.android.com/training/monitoring-device-state/doze-standby)。

## 当前验收边界

本阶段所有 AI 验证均为离线自检或历史题演练，没有发送雨课堂答案。真实雨课堂提交回执、判断题提交协议、长时熄屏联网和多品牌覆盖仍需后续验收。界面开启自动模式前会明确显示是否设有安全锁屏，不将「能唤醒并等待解锁」描述为已实现无人值守。

自检图片的正确选项每次随机生成，表中选项不是固定自检答案。所有上述测试均未手动发送。自检的答案正确仅指人工构造的简单图片，不能据此衡量课堂学科准确率。

在最终分享入口检测加入前，Kimi 3.1.4 的单图和双图初测也分别在 13,440 ms、11,288 ms 通过。适配规则修订后，手机页确实将这两项旧记录显示为「待通过」，随后完成上表复测。

历史题第一次回归在约 60,053 ms 后失败；当时诊断读取受到工具审批额度中断，最近任务和控件记录后来被其他演练覆盖，只能从阶段日志确认失败时间，无法确定具体界面/网络原因。同一个最终 APK 随后重试成功，未为重试放宽附件或答案校验。这项间歇失败仍是稳定性限制。

修正了自检页混入旧版本/其他 AI 的最近任务结果的问题。最终返回 Kimi 自检页后，电脑界面树读取两次返回空根节点，未据此宣称 UI 检查通过；用户随后在手机上确认「显示两项已通过」。自检页保持打开，未开启课堂自动模式。
