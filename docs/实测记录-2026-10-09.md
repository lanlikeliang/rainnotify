官方代码从路由保留字符串 lessonID，以 source=5 调用 checkin；GET 请求设置 X-Client: h5，后续 POST 继承该请求头。响应中的 Set-Auth 供后续 Authorization: Bearer 使用。成功条件是 code=0，不能额外要求 msg 必须恰为 OK。

官方课堂仍通过 checkin 获得 lessonToken 与 identityId，再发送 student hello。没有发现直接复用微信入课状态的只读令牌入口。用户在微信中已经入课，不意味着辅助 App 自动持有微信页面的临时监听令牌。

## 0.0.9 修复范围

- 保留课堂编号字符串类型，包括入课请求及 WebSocket hello。
- 补齐网页客户端请求头，在本客户端内存中保留并复用官方响应的 Set-Auth；请求有本域 csrftoken Cookie 时携带匹配请求头。
- 按 code=0 解析成功入课响应，兼容不返回 msg 的响应。
- 对非成功 HTTP 响应仅记录 JSON 布尔值及数字业务码，不保存响应正文；请求与响应鉴权只记录存在与否，不记录值。
- 手机入口改为“监听此课堂”，说明已在微信入课后仍需获取辅助 App 令牌，调用可能记录签到。仍由用户手动点击，不自动入课或重试入课。

这些是已观察到的兼容性差异；是否解决当天的 HTTP 400，须以安装后单次重试的真实结果为准。
