# API 正式版界面 V2：三档模式与同一套首页

2026-10-26 设计，2026-10-27 实现更新。取代“历史演练、题目导入导出、首页最近处理、独立监听按钮和自动开关、首次使用专用布局”。Compose 页面已按本规格实现；原效果图仅作设计参考，实际验证范围见 `../API_ONLY_IMPLEMENTATION.md`。

## 产品范围

正式版只保留手机直接调用 AI API。首个适配为 DeepSeek；未完成适配的服务商不显示为可选项。删除前台 AI App 路线及相关无障碍、关联启动、版本兼容性自检入口。

正式版日常界面不提供历史题演练、样本导入导出、30 秒模拟发题等研发功能，不保留对外演练入口。研发回归使用独立测试工程和合成题，不把测试功能塞回用户界面。既有原型及实测文件保留归档，不因精简界面清除用户已有资料。

API 配置仅保留当前服务的凭据配置、模型及图文自检状态/重新自检入口。自检说明“会调用当前 API，不向课堂提交”。通知配置中的一次性测试通知可以作为权限排查动作保留，不等同于题目演练。

## 首页的固定骨架

底部导航固定为 **课堂 / 题目 / 设置**。

课堂页从上到下始终是：

1. 页面标题“课堂”。
2. 当前连接信息：**当前账户、当前课堂、当前模型**。三行用同一个信息区展示，避免三张大卡。账号只展示必要的用户标识，不显示令牌。模型显示服务商与模型名及图文自检状态。
3. **一个大型三档模式控件：关闭 / 发题通知 / 自动答题**。始终显示三个档位，选中档明显高亮；控件内的大标题说明当前实际状态，下方一行解释该模式会做什么。
4. 仅在需要时显示缺项、连接异常等紧凑提示。正常状态不再放“最近处理”、统计卡或配置清单。

它在视觉和状态管理上是一个控件，三个档位可直接点选；不采用一次点击循环换档，避免从关闭意外跨进自动提交。

## 三档行为

| 档位 | 课堂监听 | 新题通知和内容 | API 调用 | 自动提交 |
|---|---|---|---|---|
| 关闭 | 停止 | 不再接收新题，保留当前已显示题目的结果 | 不启动，取消可取消的任务 | 不启动；已发出的请求无法撤销 |
| 发题通知 | 开启 | 接收、展示并提醒 | 不调用 | 不提交 |
| 自动答题 | 开启 | 同样接收、展示并提醒 | 收到有效新题后调用 | 校验后提交，并明确显示服务端确认结果 |

“自动答题”档下必须写明“收到新题后自动作答并提交”，不能只写模糊的 AI 开关。默认关闭、仅当前课堂有效。只处理成功开启后收到的新题；切档不补答之前的题目。

切换关系：

- 关闭 → 发题通知：核对账号、选定课堂、通知与本 App 运行条件；入课前提示可能记录签到。连接成功后才显示“发题通知已开启”。不要求 API Key。
- 发题通知 → 自动答题：保留同一条课堂连接，核对当前 API 配置及自检结果；首次开启本次课堂自动提交时说明上传题干原图、服务商计费及 AI 可能答错。通过后变为自动档。
- 关闭 → 自动答题：一次列出全部必要条件；完成配置并确认后启动监听，连接成功才开启自动。不得先显示成功再在后台尝试连接。
- 自动答题 → 发题通知：停止后续自动调用和可取消的当前任务，保留课堂监听；已发出的提交无法撤销，结果继续在题目页更新。
- 任意档 → 关闭：立即停止监听与自动任务；关闭按钮在准备中/异常时仍可操作。
- API Key 失效/额度等阻断性错误：停止自动，降到发题通知并显示原因；不要求用户为继续收题而修复 API。
- 雨课堂登录失效、课堂结束或切换账号：回到关闭。更换模型/Key 使自检失效，已在自动档则降到发题通知。App 重启不自动恢复提交授权。
- 临时网络重连是运行阶段，不新增第四档：保留明确的“重连中，暂未接收新题”提示，不显示正常绿色运行；恢复时检查课堂和题目时限，不补交旧题。

## 首次打开与缺项反馈

不增加欢迎页、单独的新手首页或强制逐步配置向导。首次打开和正常使用的组件位置完全相同：

| 固定字段 | 首次打开 | 配置后 |
|---|---|---|
| 当前账户 | 未授权 · 去授权 | 用户标识 · 已授权 |
| 当前课堂 | 未选择 · 授权后选择 | 课堂名 · 连接状态 |
| 当前模型 | 未配置 · 去配置 | DeepSeek · Flash · 自检通过/待自检 |
| 三档模式 | 关闭 | 关闭、发题通知或自动答题的实际状态 |

首次仅在信息区下面用一行“先授权账户，再选择课堂”作就地引导。配置完成后该行消失，布局不替换为另一套页面。通知模式允许模型一行保持“未配置，通知模式无需配置”。

点击尚不满足条件的模式时，控件仍保持原状态，底部面板列出本次缺项及直接设置入口；用户不需要猜为什么按钮灰色。完成设置返回后刷新状态，仍由用户主动选择模式，不暗中打开自动提交。

提示顺序按依赖：账号 → 课堂 → 通知/后台 → API（仅自动档）。面板汇总缺项，避免连续弹多个对话框。用户取消配置时不丢失已完成的配置，也不关闭本来正常运行的通知模式。

## 题目页

聚焦 **本次课堂最新一题**，收到新题后自动刷新；不做历史题库、不做演练界面。没有题时显示“等待课堂发题”，沿用题目页布局。

内容顺序：题型与收到时间 → 题干/选项/可放大的原图 → AI 答案 → 处理状态。AI 答案出现前使用准备/作答状态，不留不明原因的空卡；通知模式不显示虚假的 AI 进度，而是注明“当前为发题通知，不会自动作答”。

只在此页追踪当前题的处理：获取中、已获取、作答中、校验中、提交中、已提交、未提交、提交结果待确认。**收到 AI 答案不等于提交成功**；只有雨课堂确认才显示“已提交”。失败用具体原因及必要的修复入口，不提供可能重复提交的盲目重试按钮。

每个结果按题目 ID 归属；新题替换显示时，旧题迟到的响应不能覆盖新题。当前最新题在任务中被用户停止，仍须显示最后已知状态。首页不再重复处理记录。

单选、多选、填空、投票、文字主观沿用既有能力；主观答案简短。图画/音频、分组题、个人意愿投票等现有不支持的自动提交场景明确显示需人工处理，不凭界面简化抹掉限制。

## 设置页

仅保留三个紧凑分组：

- **账号**：雨课堂账号管理（授权/退出）。首页显示摘要，设置负责管理。
- **AI 服务**：当前服务商、模型、API Key 已保存状态、图文自检结果与重新自检。密钥保存后不回显；更换配置需重新验证。服务端版本变化和失败时可复检，不要求安装模型 App。
- **运行保障**：通知与声音、本 App 后台运行。系统可检测项写“已允许/未检测到限制”，厂商自启动写“需手动确认”；不能用一个勾选框假装已验证熄屏可靠性。

版本、帮助与脱敏诊断收进小型“关于与帮助”，不占首页也不伪装成主业务功能。原图/账号/凭据仍按既有隐私规则处理，诊断不含题目答案和密钥。

API 路线仍需要本 App 后台联网；部分机型需自启动/省电无限制。通知权限是提醒条件，不是后台保活保证。不再出现 AI App 自启动、关联启动、无障碍或锁屏密码设置。

## 前端实现方式

使用 Kotlin + Compose + Material 3，沿用固定 Android 16 构建基线。先用纯状态组件和 Preview 实现上述首页三种状态、题目处理阶段及配置状态；不为画图安装模拟器。

`ClassroomMode = OFF | NOTIFY | AUTO` 是唯一模式源，不再让“监听中”和“自动开关”两个独立可写布尔值互相矛盾。模式意图、实际运行阶段和可用条件分开：例如 `requestedMode`、`effectiveMode`、`connectionPhase`、`requirements`。异步连接完成才提交状态；运行异常必须反映到显眼标题与状态文字。

ViewModel 将账号、课堂服务、API 配置和题目任务汇总为屏幕状态；组件只渲染与发出操作，不直接修改服务或凭据。配置错误定位到对应设置行。测试保留在独立工程，不产生产品侧演练入口。

视觉：深青绿 `#087F76`、墨色 `#182D34`、暖灰白 `#F5F7F8`；只对当前档位和主操作强调。状态同时用文字和颜色表示；三段控件提供明确选中语义，触控至少 48 dp，支持大字体。正常页减少说明，必要说明出现在实际操作处。
