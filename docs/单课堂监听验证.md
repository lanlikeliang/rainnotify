# 单课堂监听验证

更新：2026-10-09。0.0.9 已在真实课堂取得令牌、完成 WebSocket 握手，并通过一次浏览 QQ 时的真实新题通知验证；长时熄屏联网仍待验证。此前 0.0.8 的入课请求返回 HTTP 400，修复及发题证据见 [10 月 9 日实测](实测记录-2026-10-09.md)。本文区分实现、合成测试和手机实测。

## 操作范围

用户在登录页刷新当前课堂，点击某节课的“进入课堂并监听”，阅读可能记录签到的提示并确认后，才发出入课请求。每次只监听一节课；可在页面或常驻通知中停止，收到下课消息或达到 4 小时后结束。监听期间禁止重新扫码切换账号或退出登录，可先停止再操作。

服务不会自动启动、自动恢复入课或提交答案。停止无法撤销已送达服务端的入课请求。进程被结束后需手动重新开始；当前没有服务器。

## 候选协议与边界

源码依据：[thuhollow2/yuketang 学生课堂接收逻辑](https://github.com/thuhollow2/yuketang/blob/main/yuketang.py)，本地研究副本 blob SHA 为 ce1a86ae22b966dd66bc606ed02622a7aa78eee2。本次独立实现消息监听所需部分，未运行参考项目。

| 阶段 | 实现 | 尚待核对 |
| --- | --- | --- |
| 手动入课 | 校验会话、确认所选课堂仍在当前列表，然后 POST /api/v3/lesson/checkin，source=5 | 普通版实际响应、签到副作用、与微信同时在线是否冲突 |
| 入课凭据 | 解析 msg=OK、lessonToken、identityId；只保留在内存 | 过期时长及失效消息 |
| 建立监听 | WSS /wsapp/，发送 hello、userid、role=student、auth、lessonid | 真实 hello 响应及时间线结构 |
| 新题 | hello 确认后，识别 unlockproblem 的 problem.pres / problem.prob；pres 缺失时使用已知课件 | 真题事件字段及是否有发布批次 ID |
| 延长时间 | extendtime 不当作新题通知 | 实际服务器是否还会伴随其他事件 |
| 历史同步 | hello / fetchtimeline 仅更新状态；可识别的历史解锁记录加入去重 | 断网期间是否可安全补报，暂不实现 |
| 下课 | lessonfinished 停止服务 | 实际事件与关闭顺序 |

同一课件与题目在一次监听内只通知一次；去重集合在重连时保留，最多 2048 项，手动停止或进程结束后清空。这会漏掉老师再次发布同一道题的场景。服务端发布批次、时间和截止字段还没有实际样本，当前不猜测这些字段，也不宣称可以判断所有历史重放。未识别的新题结构会显示可能漏报并记录固定类型诊断。

## Android 运行与恢复

监听使用用户可见的 specialUse 前台服务和停止操作；它不是系统保证永久运行的机制。公开发布前仍需检查渠道要求。依据：[Android 前台服务类型](https://developer.android.com/develop/background-work/services/fgs/service-types#special-use)。

通过默认网络回调处理网络丢失、网络恢复与后台联网被阻止；等待 onCapabilitiesChanged 提供网络能力，不在 onAvailable 中同步查询。回调注销与服务生命周期绑定。依据：[Android 网络状态官方指导](https://developer.android.com/develop/connectivity/network-ops/reading-network-state)。

连接以服务器 hello 确认为“正在监听”，仅 TCP / WebSocket 握手成功不计为监听通过。握手最多等待 25 秒；失败采用约 2、4、8、16、30 秒加少量随机延迟的退避，连续失败超过 8 次停止；连接稳定 60 秒后重置失败计数。重连只复用本次内存凭据，绝不重新调用入课。入课 POST 禁止 OkHttp 自动网络重试，避免响应丢失时重复签到。

所有连接回调串行处理并绑定连接代次，停止与旧连接的迟到事件会被丢弃。网络中断期间界面与常驻通知提示可能漏报。监听服务不持有长期唤醒锁，因此先前 30 秒本地通知测试不能证明本监听在深度休眠中可靠；必须测整节课和实际熄屏联网。

## 隐私与通知

凭据使用现有加密会话；课堂临时令牌不持久化。诊断仅记录固定事件类型、请求阶段、状态码和网络可用布尔值，不包含课名、课堂 ID、题目 ID、正文、答案或凭据。题目通知仅显示“雨课堂有新题”，使用原有高重要性题目渠道。诊断中真实事件 source=real，模拟通知 source=simulation，不能混合统计。

通知提交成功仍不代表实际听到声音或看到横幅；系统通知渠道、静音、勿扰、冷却以及厂商后台策略继续生效。

## 实课检查步骤

计划窗口：2026-10-09 13:30–15:05。用户将在当天启动助手进行实测；未设置定时任务。届时如需读取手机诊断，再通过 USB 连接并授权 ADB。

1. 上课前确认登录、声音、题目渠道与本 App 省电策略；刷新列表。若无法找到课堂，保留提示并反馈，不反复扫码。
2. 选择课堂，确认可能记录签到后进入。观察是否显示“课堂连接已确认”。若失败，报告页面状态即可，不发送凭据。
3. 正常使用微信课堂，记录自然发题的大致时刻、辅助 App 是否提醒；区分前台、切换 App、熄屏三个场景。
4. 有实际发题机会时，连续熄屏至少 10–20 分钟再观察声音，不以 30 秒本地模拟代替。需包含拔下 USB、手机不充电的场景，记录使用 Wi-Fi 还是移动网络；充电会影响系统休眠条件。测试完成后再接回 USB 导出本 App 诊断。
5. 自然网络切换时核对断线提示和恢复。没有可控课堂时，不为测试而干扰正常上课。
6. 下课停止监听，通过本 App 脱敏诊断核对收到事件、通知提交、重复过滤及中断时间。以人工发题记录作为漏报参考。

后续优先解决真实协议偏差与熄屏联网；再增加同题再发布判断、进程终止后的提示、其他 Android 16 品牌验证以及耗电测量。
